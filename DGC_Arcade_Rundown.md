# DGC Arcade: Comprehensive System Rundown

This document provides a comprehensive overview of the DGC Arcade platform, detailing its architecture, core functionalities, and key integrations. The analysis is presented from the perspectives of a platform owner, a player, and an investor, highlighting aspects relevant to each role.

## 1. Overall Architecture

DGC Arcade is a web-based gaming platform built with a modern JavaScript/TypeScript stack. It comprises a frontend application, a backend API server, and a PostgreSQL database managed by Neon. The system is designed to handle user authentication, game logic, financial transactions, and creator/affiliate programs.

### 1.1. Frontend

The frontend application, located in `artifacts/dgc-arcade`, is built using **Vite, React, and TypeScript**, leveraging UI components from Radix UI and styling with TailwindCSS. It interacts with the backend API to fetch data, submit user actions, and display real-time information. Key features include user dashboards, game interfaces, deposit/withdrawal forms, and creator management panels.

### 1.2. Backend API Server

The backend API server, found in `artifacts/api-server`, is an **Express.js** application written in TypeScript. It handles all business logic, data persistence, and external integrations. It exposes various API endpoints for user management, transactions, game interactions, and creator functionalities. Security measures such as JWT authentication, rate limiting, and CORS protection are implemented.

### 1.3. Database (Neon PostgreSQL)

The platform utilizes a **PostgreSQL database hosted on Neon**, providing a scalable and managed data store. The database schema is defined using Drizzle ORM and includes tables for users, transactions, game data, referral programs, and creator banking. Critical financial operations are protected with row-level locking (`SELECT ... FOR UPDATE`) to prevent race conditions.

## 2. Owner's Perspective

As an owner, understanding the platform involves managing operations, ensuring profitability, mitigating risks, and overseeing user engagement.

### 2.1. Revenue Streams and Financial Management

- **Game Mechanics**: The platform hosts various games (e.g., Blackjack, Mines, Chicken Road, Slots), each contributing to the platform's revenue through house edge. The `bets` and `transactions` tables track all financial movements related to gameplay.
- **Deposits and Withdrawals**: Integrated with **Plisio** for cryptocurrency payments, allowing users to deposit and withdraw funds. The system tracks `transactions` with statuses (pending, completed, failed) and includes robust callback handling to ensure accurate crediting of user accounts. Withdrawals are subject to velocity checks, email OTP verification, and wagering requirements to prevent fraud [1].
- **Referral Program**: A multi-tier referral system (`referrals` table) incentivizes users to bring new players, with commissions tracked and paid out to creators/affiliates. Commission rates can be overridden for specialty creators.
- **Platform Settings**: Configurable settings (`platform_settings` table) allow the owner to adjust critical parameters such as minimum withdrawal amounts, auto-approval thresholds for withdrawals, signup bonuses, and maintenance mode status. This provides flexibility in managing the platform's economics and operations.

### 2.2. Risk Management and Security

- **Fraud Prevention**: The system incorporates several fraud prevention mechanisms:
    - **Device Fingerprinting and Geo-location**: Tracks user device and location data (`device_history`, `users` geo fields) to detect suspicious activities like VPN usage or multiple accounts from the same device.
    - **Withdrawal Security**: Implements email OTP for withdrawals and checks against wagering requirements and velocity limits.
    - **Fraud Reviews**: A dedicated `fraud_reviews` table suggests a system for manual review of suspicious transactions.
- **Account Security**: User passwords are hashed (`passwordHash` in `users` table), and JWTs are used for session management. Owner-specific tools require an additional step-up OTP for sensitive operations.
- **Concurrency Control**: Financial transactions (deducting/crediting balances) use database row-level locks (`SELECT ... FOR UPDATE`) to prevent race conditions and ensure data integrity [2].

### 2.3. User and Creator Management

- **User Roles**: The `users` table defines roles (e.g., 'player', 'creator', 'owner') and account types, allowing for differentiated access and features.
- **Creator Program**: A specialized program for creators/affiliates (`creator_bank_txns`, `creator_linked_accounts`, `creator_messages`). Creators can earn commissions, tip other users with promo balances, and link personal accounts for payouts. The creator dashboard provides analytics on referrals and earnings.
- **Activity Logging**: The `activity_logs` and `admin_audit_logs` tables record significant user and administrative actions, providing an audit trail for monitoring and compliance.

## 3. Player's Perspective

From a player's viewpoint, the platform offers engaging games, a clear financial system, and incentives.

### 3.1. Gaming Experience

- **Variety of Games**: Players can access various games like Blackjack, Mines, Chicken Road, and Slots. Game-specific tables (`blackjack_hands`, `mines_sessions`, `chicken_road_sessions`) store game state and results.
- **Balances**: Players have a `balance` (real money), `promoBalance` (house credits/bonuses), and `vaultBalance` (potentially locked funds). The system displays live per-coin USD values for crypto balances [2].
- **Daily Bonuses**: The `daily_bonus_claims` table suggests a system for rewarding active players.

### 3.2. Financial Interactions

- **Easy Deposits**: Integration with Plisio allows for straightforward cryptocurrency deposits. Players receive an invoice URL, wallet address, and QR code for payment [1].
- **Transparent Transactions**: Players can view their transaction history (`transactions` table), including deposits, withdrawals, bets, and wins/losses.
- **Withdrawals**: Players can request withdrawals, subject to platform rules like minimum amounts, wagering requirements, and email verification. The system aims for instant withdrawals for smaller amounts, with larger ones potentially requiring manual approval [1].

### 3.3. Community and Incentives

- **Referral Program**: Players can generate a unique referral code to invite friends and earn commissions.
- **Creator Tipping**: Players might receive promo tips from creators, enhancing their gameplay experience.
- **Tournaments**: The presence of `tournaments`, `tournament_entries`, and `tournament_participants` tables indicates competitive events for players.

## 4. Investor's Perspective

An investor would focus on the platform's growth potential, financial health, and operational efficiency.

### 4.1. Financial Health and Growth Metrics

- **User Base**: The `users` table tracks user registrations, and `visitors` table likely tracks site traffic, providing metrics for user growth.
- **Total Wagered/Deposited**: The `users` table includes `totalDeposited` and `totalWageredAmount`, key indicators of platform activity and revenue generation.
- **Referral Network**: The `referrals` table and creator program demonstrate a built-in growth mechanism, incentivizing user acquisition through affiliates.
- **Scalability**: The use of Neon PostgreSQL provides a scalable database solution, capable of handling increased user load and data volume.

### 4.2. Operational Efficiency and Technology Stack

- **Modern Tech Stack**: The use of React, Express.js, TypeScript, and Drizzle ORM indicates a modern, maintainable, and performant technology stack.
- **Automated Payments**: Plisio integration automates cryptocurrency deposits and withdrawals, reducing manual overhead and enabling global reach.
- **Fraud Detection**: Automated and manual fraud detection mechanisms protect the platform's financial integrity.
- **Observability**: Integration with Sentry (`@sentry/react`, `@sentry/node`) suggests robust error tracking and performance monitoring, crucial for maintaining a healthy application.

## 6. Connectors and Integrations

- **Neon PostgreSQL**: The primary database, offering serverless PostgreSQL with features like branching and connection pooling. The `DATABASE_URL` environment variable is crucial for connecting to it [3].
- **Plisio**: A cryptocurrency payment gateway used for deposits and withdrawals. It requires `PLISIO_SECRET_KEY` for API access and handles IPN callbacks for transaction status updates [1].
- **Resend/Nodemailer**: Used for sending transactional emails, such as email verification codes and withdrawal OTPs. This is evident from the `mail-service.js` and `auth.ts` files.
- **Sentry**: Integrated for error tracking and performance monitoring in both frontend and backend, ensuring application stability and quick issue resolution.
- **Referral System**: The platform has a robust referral system that tracks referred users and calculates commissions, which are then managed through the creator bank.
